## 0. Как использовать этот файл

- Этот документ фиксирует правила реализации сайта BAS Agros для Казахстана.
- Утверждённую SEO-карту нельзя заменять собственной семантикой, кластеризацией или новой структурой URL.
- Полная постраничная спецификация находится в SEO-карте. Этот файл содержит её архитектурное резюме и обязательные правила разработки.
- При создании страницы брать из `02_SEO_MAP`: `url`, `page_type`, `template_type`, интент, Title, H1, направление Description, обязательные блоки, перелинковку, Schema, приоритет, волну и indexing gate.
- Любое изменение frozen URL, родительской иерархии или semantic ownership требует отдельного SEO-review.
- Потенциальные ошибки не исправлять молча. Записывать их в раздел «Открытые вопросы / Требует проверки».

## 3. О компании и бизнесе

BAS Agros предлагает семена для сельского хозяйства. В утверждённой структуре приоритет отдан кормовым травам и травосмесям. Каталог включает травосмеси, сорго, однолетние и многолетние кормовые травы. Отдельная ось навигации группирует товары по подтверждённому назначению: для сенокоса, пастбищ, медоносов и сидератов.

### Основные группы клиентов

- агрохолдинги;
- крестьянские и фермерские хозяйства;
- сельскохозяйственные предприятия;
- закупщики семян;
- для отдельных категорий: озеленители, ландшафтные компании и частные хозяйства.

### Основные сценарии обращения

1. Клиент выбирает категорию или конкретный товар и запрашивает цену.
2. Клиент уточняет наличие товара.
3. Клиент указывает желаемый объём; фиксированного минимального заказа нет, объём согласуется индивидуально.
4. Клиент выбирает CRM-вариант товара, если одной SEO-странице соответствует несколько CRM-позиций.
5. Клиент изучает условия доставки, оплаты и документы, затем оставляет заявку.
6. Клиент приходит по задаче — сенокос, пастбище, медонос или сидерат — и переходит к подтверждённому товару.

Сайт не является интернет-магазином с публичной корзиной и онлайн-оплатой, пока такая модель отдельно не подтверждена.

## 6. География и языки

- Национальный рынок первого запуска: Казахстан.
- Все 59 SEO-страниц относятся ко всему Казахстану.
- Доставка заявлена по всему Казахстану без неподтверждённых сроков, тарифов и исключений.
- Городские, областные и иные региональные SEO-страницы для Казахстана не создавать: подтверждённого отдельного регионального спроса нет.
- Geo-модификаторы распределяются по существующим национальным URL.

## 9. Типы страниц и шаблоны

### 9.1 Главная — `homepage`

- Назначение: бренд, общее предложение и навигация к каталогу.
- Интент: общий коммерческий/брендовый.
- Обязательные блоки: Hero, категории, ключевые товары, качество, доставка, FAQ, форма.
- CTA: «Каталог» и «Оставить заявку».
- Schema: `Organization`, `WebSite`.
- Правило: exact-кластер «семена кормовых трав» принадлежит `/catalog/`, а не главной.

### 9.2 Каталог — `catalog_hub`

- Назначение: основной ассортиментный хаб.
- Интент: категорийный коммерческий.
- Обязательные блоки: четыре основные категории, навигация, каталог, UI-фильтр без индексируемых параметров, CTA.
- CTA: переход в категорию.
- Schema: `ItemList`, `BreadcrumbList`.

### 9.3 Категория — `category`

- Назначение: показать товары конкретной товарной группы.
- Интент: категорийный.
- Обязательные блоки: описание назначения категории, карточки товаров, критерии выбора, CTA; FAQ только по необходимости.
- CTA: перейти к товару / оставить заявку.
- Schema: `ItemList`, `BreadcrumbList`.
- Дочерние товары используют полные вложенные URL.

### 9.4 Culture hub — `culture`

- Использовать только для Суданки и Полевицы.
- Назначение: закрыть самостоятельный общий спрос по культуре и развести виды/варианты.
- Обязательные блоки: общий ответ по культуре, сравнение видов, карточки дочерних товаров.
- CTA: перейти к конкретному товару.
- Schema: `ItemList`, `BreadcrumbList`.
- Суданка 1РС, Суданка 2РС и Сорго суданковое — разные товарные сущности.

### 9.5 Товар — `product`

- Назначение: представить конкретный товар и получить заявку.
- Интент: transactional/commercial/product с информационной поддержкой.
- Обязательные блоки: название, подтверждённое назначение, подтверждённые характеристики, CRM mapping, «Цена по запросу», «Уточнить наличие», поле желаемого объёма, доставка, документы, форма.
- Для травосмесей состав и процентные компоненты обязательны до публикации.
- CTA: «Запросить цену» / «Уточнить наличие».
- Schema: `Product` + `BreadcrumbList` в режиме `ENTITY_ONLY`.
- Не создавать `Offer`, цену, availability, Review или AggregateRating без реальных данных.
- Отсутствие `offers/review/aggregateRating` допустимо: rich result eligibility не является требованием.

### 9.6 Страница по назначению — `solution`

- Назначение: ответить на задачу применения, не дублируя товарную категорию.
- Обязательные блоки: задача, критерии выбора, только подтверждённые товары, сравнение, ссылки на canonical product URL, CTA.
- CTA: перейти к товару / запросить цену.
- Schema: `ItemList`, `BreadcrumbList`.
- Состав карточек берётся только из `17_PURPOSE_MATRIX`.
- Один товар всегда ведёт на один canonical URL; новый product URL внутри solution page не создаётся.

### 9.7 Коммерческая сервисная / trust — `commercial_service`

- Страницы: доставка и оплата; качество и сертификаты.
- Использовать только подтверждённые условия и документы.
- CTA: оставить заявку / запросить документы.
- Schema: `WebPage`, `BreadcrumbList`.

### 9.8 Корпоративная — `corporate`

- Одна страница `/o-kompanii/` объединяет сведения о компании, контакты и реквизиты.
- Обязательные блоки: подтверждённые сведения о компании, география, реквизиты, контакты, ссылки на каталог.
- CTA: перейти в каталог / связаться.

### Нормализация URL

- основной протокол: HTTPS;
- основной host: `basagros.kz`, без `www`;
- все directory-like HTML routes заканчиваются `/`;
- `http://basagros.kz/*` → HTTPS 301;
- `http://www.basagros.kz/*` → HTTPS non-www 301 одним hop;
- `https://www.basagros.kz/*` → HTTPS non-www 301;
- URL без trailing slash → slash-version 301;
- `*/index.html` и `*/index.htm` → соответствующий directory URL 301;
- не создавать redirect chains;
- sitemap, canonical и внутренние ссылки сразу используют финальную форму URL.

### Служебные маршруты

| Route | Правило |
|---|---|
| `/privacy/` | REQUIRED; HTTP 200; `noindex,follow`; не включать в sitemap; ссылка из footer |
| Unknown route | REQUIRED 404 handler; реальный HTTP 404; без canonical; не создавать публичную 200-страницу `/404/` |
| `/thank-you/` | CONDITIONAL; по умолчанию inline success; если создан — noindex, без sitemap и меню |
| `/search/` | CONDITIONAL; по умолчанию не создавать; если создан — noindex, без sitemap |

### Robots и sitemap

- `robots.txt` должен ссылаться на финальный sitemap.
- Страницы до снятия gate не включать в sitemap.
- Если gated-страница временно доступна публично для QA — `noindex` и отсутствие в sitemap.
- Не блокировать в robots.txt CSS/JS/изображения, необходимые для рендеринга.

- Адреса, телефоны, email и реквизиты — брать только из актуального подтверждённого источника.
- Характеристики, составы и фасовки — брать только из документов/CRM/материалов компании.
- Урожайность, нормы высева, агрономические свойства — только после fact-check.
- Медицинские свойства — не заявлять без допустимого подтверждённого основания.
- Фейковые фото товаров, сотрудников, производства и документов — запрещены.
- География вне Казахстана — не добавлять в текущую архитектуру без отдельного решения.
- Интеграции и аналитические системы — не придумывать.

## 26. Indexing gate

Целевое `indexability=index` в SEO-карте не разрешает публиковать пустой или неподтверждённый шаблон.

До прохождения gate:

- предпочтительно `NOT_PUBLISH`;
- если страница нужна публично для QA — `noindex` и отсутствие в sitemap.

После прохождения gate:

- `index,follow`;
- включение в sitemap;
- self-canonical;
- контроль фактического HTTP-status.

### Минимальные критерии снятия gate

- контент соответствует SEO-карте;
- заполнены обязательные блоки;
- присутствуют только подтверждённые товарные и бизнес-данные;
- формы работают с реальным success/error;
- метаданные и canonical корректны;
- Schema соответствует видимому контенту;
- нет placeholder-текста;
- нет битых ссылок и ресурсов;
- responsive QA пройден;
- Lighthouse mobile пройден;
- страница включена в финальную перелинковку.

## 28. Definition of Done для страницы

### Content

- URL, интент, H1 и содержание соответствуют `02_SEO_MAP`;
- обязательные блоки заполнены;
- нет выдуманных фактов;
- нет placeholder-текста;
- для травосмесей указан подтверждённый состав;
- для solution pages используются только подтверждённые товары.

### SEO

- уникальные Title и Description;
- один H1;
- canonical;
- корректная indexability с учётом gate;
- внутренние ссылки по `06_INTERNAL_LINKING`;
- breadcrumbs;
- Schema при необходимости;
- корректный HTTP-status;
- sitemap только после gate.

### Frontend

- responsive на обязательных ширинах;
- нет horizontal scroll и layout break;
- нет ошибок Console;
- интерактивные элементы работают с клавиатуры;
- фильтры не создают crawlable query links.

### Performance

- LCP оптимизирован;
- размеры медиа зарезервированы;
- изображения оптимизированы;
- CLS контролируется;
- лишний JS отсутствует;
- три mobile Lighthouse runs;
- Performance ниже 90 блокирует публикацию.

### Forms

- payload содержит корректный контекст страницы и CRM mapping;
- нет duplicate submit;
- loading/success/error отражают реальный ответ;
- персональные данные не логируются;
- секретов во frontend нет.

### Accessibility

- keyboard navigation;
- labels;
- visible focus;
- alt;
- contrast;
- доступные меню, FAQ и модальные элементы.

### QA

- desktop и mobile;
- Console и Network;
- все ссылки;
- все формы;
- все интерактивные компоненты;
- canonical, robots и sitemap;
- отсутствие 404/403 у используемых ресурсов.

### Release

- проектная команда запускает фактический quality command репозитория;
- если в репозитории используется `npm run quality:all`, команда должна проходить;
- Lighthouse mobile выполнен;
- indexing gate снят явно.

## 31. Обнаруженные ограничения и риски

- `CORE SERP VERIFIED` означает проверку архитектурного ядра по 29 запросам, а не каждого товарного запроса.
- Generic-запрос «семена донника» нельзя выдавать за exact-подтверждение спроса на Донник жёлтый.
- Raw sum вариантов ключей — диагностическая величина, а не оценка объёма рынка.
- Пустые production routes нельзя индексировать только потому, что в карте указано целевое `index`.
- Временный общий CRM ID `1190` требует обязательного `site_product` discriminator.
- Недостоверное наличие, цены `0/1 ₸`, неподтверждённые характеристики и составы могут привести к неверным заявкам и Schema.
- Solution pages легко превратить в дубли категорий; они обязаны отвечать на задачу применения и ссылаться на единственные product canonical URL.

## 32. Правила для ИИ-агента перед созданием каждой страницы

1. Найти строку страницы в `02_SEO_MAP`.
2. Проверить parent/child hierarchy в `03_URL_TREE`.
3. Взять шаблон из `template_type` и `14_TEMPLATE_SPECS`.
4. Взять Title и H1 без самостоятельной смены интента.
5. Прочитать обязательные content/commercial/proof blocks.
6. Для товара проверить `16_CRM_MAPPING`.
7. Для solution page проверить `17_PURPOSE_MATRIX`.
8. Взять ссылки только из `06_INTERNAL_LINKING`.
9. Проверить data/content gate и открытые вопросы.
10. Не заполнять отсутствующие факты догадками.
11. Реализовать страницу и пройти Definition of Done.
12. Не снимать `noindex` и не включать URL в sitemap без явного прохождения gate.
